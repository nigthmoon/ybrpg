# 宝物吸收机制策划方案

> 目标：让背包/阵容中的武将可以把一个指定品质的宝物「吸收」进空突破槽位，
> 宝物消失，武将获得其属性与特效，并永久写入该实例的突破数据。
> 同名其他武将不共享，不干涉图鉴，且预留品质/槽位类型接口。

---

## 一、现状梳理（改之前先确认事实）

| 关注点 | 现状 | 关键位置 |
|---|---|---|
| 角色突破数据 | 每个实例存 `window.charBagData[instanceId].tupoList`（可变数组，空位为 `null`）+ `tupolevel` | `characterList.js` `generateTupoList_new`，空位即 `null` |
| 突破属性结算 | `computeStats` 遍历 `tupoList[0..tupolevel)` 处理 `self_stat_flat`/`self_stat_percent`/`team_*`，已支持 攻/防/血/速/命中/闪避/暴击/抗暴/暴伤/守护/破击/格挡/增伤/减伤/治疗等 | `game/system.js` |
| 突破特效结算 | `buildUnit` 把 `tupoList` 里的 `skill_effect`/`passive_effect`/`self_energy`/`death_effect`/`behit_effect` 编译进单位 `skills` | `battle/battle_refactored.js` |
| 属性来源 | `buildUnit` 直接读 `data._compiledStats`（由 `computeStats` 预编译），不重复结算 | `battle/battle_refactored.js` |
| 宝物实例 | `treasureInventory[instanceId] = { baseId, equippedBy }`，缺 `quality`/`star` 字段 | `gameData.js` |
| 宝物两种定义 | `equip.js`（含 `atk/baoji/star` 倍率 + `effectSkills` 引用突破库）；`treasureList.js`（含 `type`/`effect(ctx)` 另一套触发 API） | `equip.js`、`treasureList.js` |
| 宝物属性计算 | `Bag.stats(instanceId)` 已按强化等级算出 `atk/def/hp/spe/mingzhong/shanbi/baoji...` 合计 | `game/system.js` |

**关键结论**：只要把「被吸收的宝物」翻译成一个已有的突破 buff 对象写进
`instData.tupoList[index]`，属性（`computeStats`）和特效（`buildUnit`）两条管道都会
**自动生效**，无需大改战斗内核。真正要做的是：① 新增一种 buff 类型承载「属性+特效」组合；
② 宝物→buff 的翻译层；③ 品质/槽位要求的接口与 UI。

---

## 二、核心设计：新增突破 buff 类型 `treasure_absorb`

吸收后写入空槽的不再是 `null`，而是一个统一结构（一个对象同时被 `computeStats` 和 `buildUnit` 理解）：

```js
{
  type: 'treasure_absorb',
  absorbed: true,
  sourceTreasureId: 'wusheng',     // 来源宝物（用于 UI 显示"吸收自【武圣】"）
  sourceInstanceId: 't_xxx',       // 原实例（已销毁，仅留痕）
  quality: 'epic',                 // 写入时记录品质，便于将来替换/平衡
  flat: { atk:2000, baoji:2000 },  // 已按强化等级算好的最终属性（直接复用 Bag.stats）
  ability: null | <特效对象>        // 见第四节
}
```

两个结算点各取所需（互不重复）：
- `computeStats`：新增 `case 'treasure_absorb':`，把 `.flat` 当作 `self_stat_flat` 累加。
  `buildUnit` 读 `_compiledStats`，自动带上，**零重复**。
- `buildUnit`：新增 `case 'treasure_absorb':`，若 `.ability` 存在，按 ability 的 `type`
  走现有分支（`skill_effect`→`adaptBreakthroughSkillEffect`；`passive_effect`→推 `effectId`；
  `self_stat_percent`→并入百分比）。

## 三、数据结构改动（含品质/槽位类型预留）

**1. 宝物实例**（`treasureInventory[instanceId]`）增加字段：
```js
{ baseId, equippedBy, quality:'epic', star:10 }  // star=强化等级，quality=品质
```
`quality` 在掉落/合成时赋值（先默认按 `baseDef.quality` 或随机，后续做掉落权重）。

**2. 槽位要求**（与 `tupoList` 平行的格位，定义在角色模板上，不随实例变）：
```js
// characterList 角色对象新增
tupoSloReq: [ {quality:'rare', type:'atk'}, null, {quality:null,type:'any'}, ... ]  // 与 0~19 对齐
```
- `quality`：吸收所需最低品质（`null`=不限）。
- `type`：槽位类型/标签，如 `'atk'`(攻击向)/`'def'`(防御向)/`'util'`(功能向)/`'any'`。
- 只有 `tupoList[i]===null` 且 `tupoSloReq[i]` 存在 的格子才是「可吸收空槽」。

**3. 预留接口**（集中放一个配置模块，如 `src/treasureQuality.js`）：
```js
export const TREASURE_QUALITY = {
  common:    { name:'普通', color:'#9e9e9e', powerFactor:1.0 },
  rare:      { name:'稀有', color:'#4aa3ff', powerFactor:1.0 },
  epic:      { name:'史诗', color:'#b06bff', powerFactor:1.0 },
  legendary: { name:'传说', color:'#ffb347', powerFactor:1.0 },
};
// 将来可让 low-quality 槽位对 high-quality 宝物做 powerFactor 折扣，纯数据驱动
export function canAbsorb(treasure, slotReq){
  if(!slotReq) return false;
  if(slotReq.quality && qualityRank(treasure.quality) < qualityRank(slotReq.quality)) return false;
  if(slotReq.type && slotReq.type!=='any' && treasure.type!==slotReq.type) return false;
  return true;
}
```
> 这样「明确划分品质、空槽位划分品质和类型」只需填数据，逻辑不动。

## 四、翻译层：宝物 → `treasure_absorb`（方案重点）

**A. 属性部分（最简单，必做）**
直接 `const s = Bag.stats(treasureInstanceId)`，把 `s.atk/def/hp/spe/mingzhong/shanbi/baoji/...`
拷进 `flat`。用户举例的「攻200暴击2000强化10级→攻2000+暴击2000」由 `Bag.stats` 自然得出，
**无需重写倍率**。

**B. 特效部分**（宝物分两套 API，统一收敛为「ability 契约」）：
- **`equip.js` 宝物（有 `effectSkills`）**：`effectSkills` 是突破库 ID 数组。直接转成
  `ability = { type:'skill_effect_group', effectIds:[...] }`，`buildUnit` 里循环
  `adaptBreakthroughSkillEffect` 即可——**零翻译成本**。
- **`treasureList.js` 宝物（`type`/`effect(ctx)`）**：与突破 API 不同（用 `ctx.unit`/`ctx.calcDamage`，
  突破用 `this`/`target`）。建议选 (2)：
  1. *逐宝物手写翻译*：把每个 `type` 映射到突破 `trigger`，把 `effect(ctx)` 包成 `content(this,target)`。
  2. **(推荐) 保留原 `effect(ctx)` 引擎**：`ability = { type:'raw_treasure_effect', trigger:<映射>,
     effect:<原函数>, desc }`，`buildUnit` 新增 `raw_treasure_effect` 分支，用「触发时机映射表」
     把突破 `trigger` 转回 `treasureList` 的 `ctx` 再调用 `effect(ctx)`。新增宝物不用改翻译层，
     且「增伤20%」「技能后回血」等都能直接套用。

> 无论哪种，最终都收敛为 `ability` 这一个字段，`buildUnit` 只多一个 `case`，战斗内核不动。

**C. 纯属性宝物**（如只有 atk/baoji，无 `effectSkills`/`effect`）：`ability:null`，只走 `flat`。

## 五、UI 流程（改动集中在 `mode.js` 突破面板）

1. 渲染突破列表时，遇到 `tupoList[i]===null` 且 `tupoSloReq[i]` 存在 → 显示**「吸收宝物」按钮**
   （带槽位类型/品质提示）。
2. 点击打开**宝物选择弹窗**：从 `treasureInventory` 取 `equippedBy` 为空的宝物，用 `canAbsorb`
   过滤，展示图标/属性/特效预览。
3. 确认 → 调新 API `absorbTreasureIntoSlot(instanceId, slotIndex, treasureInstanceId)`：
   - `Bag.remove(treasureInstanceId)`（宝物消失）；
   - 写入 `instData.tupoList[slotIndex] = 翻译后的 treasure_absorb 对象`；
   - `Stat.final(instanceId)` 重算属性 → 刷新面板 → 存档。
4. **同名不共享**：因为写的是 `instData.tupoList`（实例级），其他同名武将的 `tupoList` 不变，
   自然「需重新培养」。
5. **不干涉图鉴**：图鉴读的是角色**模板**的 `tupoList`（`characterList[charId].tupoList`），
   实例吸收只改 `charBagData`，图鉴无感。
6. 预留「替换/取出」：`treasure_absorb` 带 `sourceInstanceId`/`quality`，将来做「覆盖吸收」或
   「返还」只需加一个反向 API，数据结构已支持。

## 六、持久化

`instData.tupoList` 与 `treasureInventory` 都已在 `gameData.js` 的存档/读档中覆盖，
吸收结果**自动随存档保存**，无需新存储。

---

## 七、建议实施顺序（最小可用 → 完整）

1. **Phase 0（接口预留）**：新增 `src/treasureQuality.js`（品质枚举 + `canAbsorb`），
   角色模板加 `tupoSloReq` 字段（先全填 `{type:'any',quality:null}` 不影响现有逻辑）。
2. **Phase 1（属性吸收 MVP）**：`equip.js` 类宝物 → `flat` 翻译；`computeStats` 加
   `treasure_absorb` 分支；`mode.js` 加吸收按钮+选择弹窗+`absorbTreasureIntoSlot`。
   **先只做属性，验证「攻2000+暴击2000」进战斗**。
3. **Phase 2（特效吸收）**：`effectSkills` → `skill_effect_group`；`buildUnit` 加分支。
   再做 `treasureList.js` 的 `raw_treasure_effect` 适配。
4. **Phase 3（品质/类型约束）**：掉落时赋 `quality`，`canAbsorb` 真正生效，UI 显示品质色与槽位匹配提示。

---

## 八、风险与开放问题（需拍板）

- **平衡性**：吸收等于「白送一个突破格+宝物」，是否要消耗资源（金币/材料）或限制每角色吸收次数？
  建议先不限，数据驱动可调。
- **宝物「消失」的不可逆**：是否允许「取出/替换」？建议数据结构已留 `sourceInstanceId`，
  但 Phase 1 先不做返还。
- **`treasureList.js` 与 `equip.js` 两套宝物定义并存**：吸收翻译要覆盖两套，建议长期合并为一套
  （都带 `quality`/`star`/`flat`/`ability`）。
- **`team_stat_flat` 类宝物**（全队增益）：吸收进个人突破格后，是否仍按「全队」生效？
  建议吸收后降级为 `self`（只作用自身），避免突破格变成全队发动机。
